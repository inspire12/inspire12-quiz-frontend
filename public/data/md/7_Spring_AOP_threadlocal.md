1. Spring AOP의 구성 요소에 대한 설명 중 틀린 것은?
A. JoinPoint는 부가기능을 적용할 수 있는 지점을 의미함
B. Advice는 언제 부가기능을 실행할지 정의하는 메소드임
C. Pointcut은 어떤 클래스에서 실행될지를 결정하는 기준임
D. Aspect는 메소드의 반환 값을 기준으로 프록시를 생성하는 객체임

정답: D
해설: Aspect는 공통 로직을 모아둔 클래스이며, 프록시 생성은 @EnableAspectJAutoProxy가 담당함. 반환 값을 기준으로 프록시를 만드는 건 아님.
출제의도: AOP 구성 요소의 명확한 역할과 용어 혼동 여부를 확인하기 위함.

2. 다음 중 관심사 분리(SoC)의 목적과 가장 거리가 먼 설명은?
A. 핵심 로직이 아닌 공통 로직을 한 곳에 모아 관리함
B. 코드의 가독성과 유지보수성을 높이기 위해 사용함
C. 객체지향 설계에서 중복을 제거하기 위한 방법임
D. 다양한 기능을 하나의 클래스에 넣어 응집도를 높인다

정답: D
해설: SoC는 하나의 클래스가 한 가지 역할만 하도록 분리하는 개념임. 다양한 기능을 하나에 몰아넣으면 응집도가 아니라 결합도가 높아짐.
출제의도: 좋은 코드의 원칙을 AOP 관점에서 얼마나 잘 이해했는지 확인.

3. AOP를 이용해 부가기능을 적용할 때의 장점으로 보기 어려운 것은?
A. 비즈니스 로직에 집중할 수 있음
B. 공통 기능의 재사용성과 통일성을 높일 수 있음
C. 성능 향상을 위해 반드시 모든 메소드에 적용해야 함
D. 중복 로직 제거로 코드의 양이 줄어듦

정답: C
해설: AOP는 모든 메소드에 무조건 적용하면 오히려 성능 저하가 생길 수 있음. 핵심 로직 외에 필요한 부분에 선별적으로 적용하는 게 원칙임.
출제의도: AOP의 장점이 무조건 적용이라는 오해 없이 선택적 적용 원칙을 알고 있는지 점검.

4. 다음 중 @Around Advice 내부에서 핵심 로직 실행을 나타내는 코드로 틀린 것은?
A. joinPoint.proceed()
B. return joinPoint.proceed();
C. proceedingJoinPoint.execute()
D. Object result = joinPoint.proceed();

정답: C
해설: ProceedingJoinPoint는 proceed() 메서드로 실행됨. execute()는 존재하지 않음.
출제의도: 실제 AOP 코드 작성 시 핵심 실행부 위치와 메서드 사용법을 알고 있는지 확인.

5. ThreadLocal에 대한 설명 중 틀린 것은?
A. 쓰레드 간에 공유되지 않는 독립적인 저장 공간임
B. 사용자 인증 정보 등을 쓰레드 단위로 안전하게 저장할 수 있음
C. 한 요청 내에서 필터 → 인터셉터 → 컨트롤러에서 값 공유가 가능함
D. 모든 요청 간에 공유가 되므로 데이터 일관성 유지에 유리함

정답: D
해설: ThreadLocal은 요청 간 공유되지 않으며, 오히려 요청 단위로만 사용되는 게 장점임. 모든 요청에 공유하면 오히려 위험함.
출제의도: ThreadLocal의 실제 작동 범위와 사용 목적을 이해했는지 확인.
