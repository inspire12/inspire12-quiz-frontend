1. NoSQL의 사용 배경으로 보기 어려운 것은?
A. 데이터 유형이 단순하고 구조가 고정적임
B. 대규모 비정형 데이터 처리가 필요함
C. 수평 확장이 용이해야 함
D. 실시간 분석 및 응답 속도가 중요함

정답: A
해설: NoSQL은 오히려 복잡하고 구조가 고정되지 않은 데이터 처리에 유리함.
출제의도: RDB와 NoSQL의 쓰임새를 구분하고 있는지 확인.

2. Elasticsearch의 개념에 대한 설명 중 틀린 것은?
A. Elasticsearch는 문서 기반의 분산 검색엔진임
B. SQL 쿼리를 그대로 활용하여 데이터를 조회할 수 있음
C. 데이터는 JSON 형태로 저장되며, 검색 최적화됨
D. 실시간 검색이 가능하고 비정형 데이터에 강함

정답: B
해설: Elasticsearch는 SQL이 아니라 DSL(Query DSL) 또는 JSON 기반 쿼리를 사용함. SQL과 유사한 일부 인터페이스는 있으나 제한적임.
출제의도: Elasticsearch의 쿼리 방식과 SQL과의 차이점을 인지했는지 판단.

3. Elasticsearch의 구조 설명 중 틀린 것은?
A. 하나의 Cluster는 여러 Node로 구성됨
B. Index는 데이터의 논리적 저장 단위임
C. Shard는 물리적 데이터를 저장하지 않음
D. Document는 실제 데이터 단위로 JSON 형태임

정답: C
해설: Shard는 데이터를 실제로 저장하는 물리 단위임. 하나의 Index는 여러 Shard로 분할 저장됨.
출제의도: 구조 단위별 개념을 혼동 없이 알고 있는지 확인.

4. NoSQL의 쓰기 중심 설계에서 고려해야 할 요소로 보기 어려운 것은?
A. 빠른 저장과 수집 우선 처리
B. 읽기 최적화를 위한 정규화
C. 실시간 분석을 위한 스트리밍 처리
D. 다양한 포맷의 데이터 수용

정답: B
해설: NoSQL은 읽기보다 쓰기 중심이고, 정규화가 아닌 비정규화 구조가 일반적임.
출제의도: NoSQL에서 자주 혼동되는 정규화/비정규화 개념을 구분할 수 있는지 평가.

5. 데이터 저장 패턴 중 ELT 방식의 설명으로 틀린 것은?
A. 데이터를 먼저 저장한 후 나중에 변환함
B. ETL보다 실시간 처리에 더 적합함
C. 데이터를 가공한 뒤 저장소에 적재함
D. 빅데이터 및 NoSQL 환경에서 자주 쓰임

정답: C
해설: ELT는 저장 후 변환이며, 가공 → 저장은 ETL 방식임.
출제의도: ELT와 ETL의 순서 및 목적 차이를 명확히 알고 있는지 판단.
